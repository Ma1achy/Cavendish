## 1. What the owner can newly do

- **Keep scenes as files.** `save my-scene.ron` writes the scene; `load my-scene.ron` reads it;
  `cav get|set|ls|schema <scene> [path]` read and edit a file from the command line.
- **Edit anything from anywhere, one way.** The properties panel has an editor for every field,
  made from the schema (unit, range and the doc string as hover text). A panel, the console
  (`set`, `add`, `remove`), `cav set`, and an agent over MCP (`scene_set`, `scene_ls`, an inline
  spec to `scene_load`) all issue the same commands. Undo and redo take back any of them.
- **Replay a session.** `journal save session.json`, then `cav replay session.json --out dir/`
  re-runs it and writes the same files, byte for byte.
- **Give each tower its own clock.** `array.towers[n].timing.offset`; the timeline has one lane
  per tower and a lane can be dragged sideways to set the offset; `show flight` draws the atoms'
  space–time diagrams of every tower on one absolute time axis.
- **Switch instrument.** `preset aice` or `preset aion10` (or a file of your own); `compare aice`
  draws every plot a second time for the same scene on the other instrument.
- **Design a cadence.** Cycle jitter (symmetric or positive only; a random walk or about a grid),
  alternation, planned gaps, a loss probability and a daily window live in `array.schedule`;
  `show cadence` draws the spectral window with the predicted alias lines, floors and the loss of
  sensitivity, live, as the fields are edited. Uneven sampling is read with the NUFFT
  Lomb–Scargle.
- **Run headless and get a bundle.** `cav run scene.ron --out dir/` writes `.npy` arrays named
  and shaped as v1's `StateBundle`, each tower's own readout times, the numerics block and the
  per-tower error estimate.
- **Export figures.** `figure periodogram --preset paper-column --out fig.pdf` (also `.svg`,
  `.png`) from the console, `cav figure …` and MCP: the figure, the data behind it (`.csv` or
  `.npy`) and a JSON of axes, units and provenance. `python/cavendish_figures` redraws one from
  its data with matplotlib in the same house style.
- **Find your way round the code.** `docs/ARCHITECTURE.md`, `CONTRIBUTING.md` and a recipe in
  `docs/extending/` for each kind of thing that can be added.

### One edit path

```
editor / drag / console line / cav set / MCP scene_set / a loaded file
        └──► Command::{Set, Insert, Remove, Load, Undo, Redo, …} ──► Engine::apply
                 │ check (paths in cav-sim, then SceneSpec::validate)      │ journal (the replay)
                 │ history: the inverse edit, by bytes, oldest dropped     │ log: the console line
                 └──► forward workers (stale, then refined) ──► Query / Export
```

- **Paths** (`cav_sim::paths`): the note's option A, finished. A path is parsed once into
  segments (`array.towers[2].timing.offset`, an enum through its variant:
  `bodies[0].motion.Static.position`); `get`, `set`, `insert`, `remove`, `ls` and `schema_at` walk
  a `serde_json::Value` of the spec and its JSON Schema. Units (`x-unit`) and the stage an edit
  invalidates (`x-stage`) are `schemars` attributes on the fields; `diff(a, b)` names the earliest
  stage. The engine, `cav get|set|ls`, MCP and the editors all call this one module.
- **Undo** is an inverse edit per step (a few bytes for a `Set`), with whole scenes kept only for
  `Load`. The history is bounded by bytes (§3.1).
- **Export** is a command, so a session's journal says what it wrote. Replaying a journal never
  writes to the paths in it: the replayer names a directory and exports land there by file name,
  or are skipped. Bundles, scenes and journals are written by the engine; figures by an exporter
  the client installs (`cav-plot`), since the engine does not draw.
- **Non-finite numbers in JSON.** Replies carry floats through `cav_sim::json_f64`: finite values
  as numbers, `±∞` as the strings `"inf"` and `"-inf"`, NaN as `"nan"` (its bits are not kept, and
  no bundle may hold one). A half-space's single-interferometer channels now survive MCP.

### Per-tower time

`TowerSpec.timing.offset` (seconds, default 0) shifts every shot of that tower. `ArraySpec.schedule`
is the array's clock: when shot `k` is launched, and which shots are not taken. Tower `d` reads
shot `k` out at `launch_k + offset_d + 2T`. All towers take the same number of shots, so the
arrays stay rectangular `(T, D)`; a shot not taken (a planned gap, the daily window, a lost shot)
is a slot whose `valid` flag is false and whose value is 0, never NaN. With no offsets and the
uniform schedule every number is the bits S1 produced (`zero_offsets_are_the_old_schedule`).

### Cadence (`cav_core::cadence`, `cav_sim::schedule`)

Random numbers are a keyed hash of `(seed, stream, tower, shot)` (SplitMix64), never a stream
with state, so thread count and order cannot matter. The designer draws the *expected* spectral
window from closed forms (uniform, cycle jitter as a random walk, jitter about a grid, alternation,
planned gaps, loss) and one *realisation* for the scene's seed by direct sum (short runs) or NUFFT.

### The bundle (`cav_sim::bundle`)

```
dir/manifest.json      names, shapes, dtypes; the numerics block; the scene, verbatim; the sign note
dir/scene.ron          the scene as saved
dir/time.npy               (T,)      f8  each shot's readout on the array's clock, seconds
dir/detector_time.npy      (T, D)    f8  each tower's own readout time, seconds
dir/valid.npy              (T, D)    b1  whether the shot was taken
dir/signal.npy             (T, D)    f8  ΔΦ, radians; lower minus upper unless the scene says otherwise
dir/signal_per_ifo.npy     (T, D, 2) f8  δφ₁ (lower), δφ₂ (upper), radians
dir/detector_placement.npy (D, 7)    f8  x, y, z of the base, then the quaternion w, x, y, z
dir/source_position.npy    (S, T, 3) f8  each body's position at `time`, metres
dir/source_mass.npy        (S,)      f8  kilograms
dir/error_estimate.npy     (D,)      f8  the largest quadrature estimate of any shot, radians
```

Names and shapes are v1's (`design/state.md` at `v1-final`), measurement first. Everything is f64:
the engine is f64 on the CPU until S5. The manifest says `sign: lower minus upper (δφ₁ − δφ₂);
v1 bundles are upper minus lower`. A bundle is written only from a refined signal; a NaN anywhere
is refused with its place. Arrays are written through a buffer, so writing costs no second copy.

### Figures (`cav-plot`)

A plot is built once as a display list in points (1/72 inch): lines, rectangles, circles, text.
The application paints the list with egui; SVG and PDF are that list written out, with text as
glyph outlines read from the two fonts already in the binary (Ubuntu Light and Ubuntu Mono, with
`skrifa`, which egui already compiles), so a figure looks the same wherever it is opened and the
PDF needs no font machinery; PNG is the list painted by egui's renderer at the stated resolution.
The PDF writer is in-house (one page, one uncompressed content stream; no dependency). A view of
the 3-D scene is exported as PNG, or as an SVG/PDF holding that picture; vector drawings of the
scene are S4's paper style. Presets: `paper-column` (85 mm), `paper-full` (178 mm), `slide`
(254 × 143 mm), `poster` (400 mm), `screen` (the application's dark theme); `paper` periodograms
are the house style of VALIDATION §3 item 8 (log y, grey floors at 1e-4 and 1e-5 rad/√Hz, stems
for the comb, a diamond at the ULDM benchmark).

### 3.3 Criteria written before measuring

- **R3.** The note measured 0 of 10⁷ through JSON with `float_roundtrip` and through RON. Expected
  here: 0 of 10⁶ each, through the typed struct and through `serde_json::Value`.
- **R7.** Each shot's value depends only on the scene and its own readout time; nothing is summed
  across threads; the sum over sources is in the scene's order. Expected: 0 bytes differing in
  every arm. The claim is **same binary, same platform, CPU path** (the note, §2.4: `sin` and
  `cos` are the platform's).
- **R8.** A tower's readout is `launch + offset + 2T`; with offset 0.0 that is the same addition
  as S1's `launch + 2T`, so the bits are S1's. With an offset δ the tower's shot is read at a time
  that differs from "the synchronous scene at t + δ" by at most one rounding of the time (2e-16 of
  it), so the phases agree to 1e-12 of the peak with three decades in hand.
- **R13, each against the note's closed form:**
  - *uniform*: `|W|` is the Dirichlet kernel, to 1e-12 (the note: 1e-14).
  - *alternating* `T_A, T_B`: sidebands at `k/T_s` of relative height `|cos(π k T_A / T_s)|`,
    to 1e-3 at N = 2000 and equal at N and 10 N to 1e-3. Control: with cycle jitter in place of
    alternation the height at N and 10 N differs by more than 30%.
  - *planned gaps*, L of every P: lines at `k/(P T₀)` of height `|sin(πkL/P) / (L sin(πk/P))|`,
    to 1e-9 for a whole number of periods.
  - *cycle jitter* (random walk), positive and symmetric, δ = 0.1 and 0.3 s at T₀ = 5 s, N = 500:
    the mean of `|W|²` over 2000 keyed seeds at the alias `1/T̄` and at two frequencies off it is
    the closed form to within 3 standard errors of that mean (the standard error measured from the
    seeds) and within 8%.
  - *jitter about a grid*: `E|W|² = |ψ|²|D_N|² + (1 − |ψ|²)/N` at the first alias, the same
    criterion; and the line's height at N and 10 N equal to 3% (it does not recede).
  - *loss*: the floor `p/((1 − p)N)` for p = 0.01 and 0.05 at N = 4000, away from the lines: the
    mean over 400 seeds and 64 frequencies within 5% (the note saw 6% and 1.4% with 300 seeds and
    could not say whether the 6% was noise; if it is not, this fails and is explained, not moved).
  - *alias ratio against N*: the predicted `√E|W|²` at `1/T̄` falls with a local slope between
    −0.40 and −0.50 from N = 5×10³ to 10⁵ for δ = 0.1 and 0.3 s, and equals the note's 0.660,
    0.382, 0.263 (N = 5×10³) and 0.175, 0.089, 0.060 (10⁵) to three figures.
- **R14.** S1 measured the NUFFT Lomb–Scargle at 3e-15 of the peak against the exact one;
  through the engine, on a jittered and gapped series of a comb scene: ≤ 1e-9.
- **R17, the palette.** Written before the `dataviz` validator was run: every pair of the eight
  series colours differs by ΔE ≥ 12 (CIEDE2000 or the skill's own measure) in normal vision and
  under simulated protanopia, deuteranopia and tritanopia; the first four also differ in lightness
  by at least 8 L* from each other so that they survive grey print.
- **`quick` after a rebuild.** Measured first, in §7.2, before anything is changed for it.

### 7.7 What the measurements and the demo found (kept as they happened)

- **`cav replay` refused its own journal.** The demo's replay of a session that exported a
  bundle failed: "the signal is still being computed". A replay made its own engine with a
  typed line's patience, a tenth of a second. The exit test had not seen it because its scenes
  are read in less than that. Now a replay waits (`REPLAY_PATIENCE`, an hour, or `--patience`),
  with `a_replay_waits_for_the_signal_an_export_needs`; and `cav replay` draws the figures a
  journal exported, which it could not (`cli_replay_writes_the_bundle_and_the_figure_a_session_exported`).
- **A drag's journal entry merged into an earlier set on replay** (found by the exit test while
  it was being written): the journal now keeps the first step's flag.
- **The research note's 30-line `.npy` writer** misses two of numpy's padding rules; ours is
  held to files numpy wrote. The note's numbers for planned gaps are for 40 of 100, not 4 of 10
  (both are in the case). The note's "6%" on the loss floor was not reproduced: 2.9% and 0.8%.
- **The AICE preset was refused** by `cycle > 2T` (its cycle is exactly 2T): the rule is `≥`.
- **A dense signal cannot show two towers whose signals are identical** (towers 4 and 5 of the
  comb are mirror images and read the same to the bit): the criterion "every tower visible" was
  restated as "every distinct series", the threshold left alone.
- **A recipe test that named itself**: the first form of `the_recipes_name_things_that_exist`
  could be satisfied by its own source; its file is left out of what it searches.
- **Not fixed:** in `paper-column` a harmonic's label written to the left of its stem can cross
  the stem before it (seen in `figures/periodogram-paper-column.png`). Labels avoid each other,
  not stems.

### 7.9 Departures from the plan and the research note

1. `cav-plot` is a crate REBUILD §3.1 does not have (S1's review, finding 8).
2. `Export` on replay writes into the replayer's directory or nowhere, never where the journal says.
3. `cycle ≥ 2T`, not `>` (the AICE preset).
4. `serde_json` with `preserve_order` and `float_roundtrip`: paths and files keep the spec's order, and every f64 survives.
5. The build's revision is asked of git at run time, not compiled in: a rebuild for every commit would cost `quick` its gate.
6. Lanes are dragged with Shift held (a plain drag scrubs).
7. `compare` is global, drawn as two plots one above the other, not an overlay.
8. AICE launches at 21.236 m/s (the rule with ⁸⁷Sr), not VALIDATION's 21.27.
9. One schedule for the array, loss drawn per tower; per-tower instruments and jitter are S15's.
10. The smallest detectable tone is shown as a factor and a floor from the closed forms, not simulated.
11. `mass` is now an `Insert`; the old command is gone from the journal's vocabulary.
12. Dependencies are optimised in dev, and three workspace crates at `opt-level = 1` (§7.2).
13. The figure bound's test lives in `cav-plot`, not `cav-memtest` (the dependency table).
14. The Python tests run under their own runner; pytest is not installed and was not added.
15. A figure's CSV holds the whole series, not only the span shown; the span is in the JSON.
16. The shot-noise floors are named in the key, not written on the lines.
