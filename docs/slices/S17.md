# S17 — in the browser

Slice brief. Asked for by the owner on 24 Nov 2026, after S3 (`s3-voxel-bodies`): the whole
application as a web page on GitHub Pages, compiled to WebAssembly with WebGPU by a GitHub Actions
workflow on every push to `main`. Numbered S17 because S0–S16 are taken; it depends on nothing after
S3 and runs now. Plan: `plan/REBUILD.md` §9 (row S17), §5.1 (the API never
blocks on a solve), §6 (the viewer), §8 (local tiers). Research: `docs/research/web-build-and-pages.md`
("the note"), followed except where §6 says. Tasks: `plan/tasks.yaml`, TASK-S17-01 (the build) and
TASK-S17-02 (the workflow and the site).

Site: **https://ma1achy.github.io/Cavendish/**

## 1. What the owner can newly do

- **Open Cavendish in a browser** (Chrome or Edge on Windows, macOS or ChromeOS; Safari 26; Firefox
  141+ on Windows) with nothing installed: the same window as natively — menus, outliner,
  properties and their editors, the 3-D panes (iso, plan, sections, the octree view and its
  overlays, voxel colouring), the timeline with its lanes, signals, periodograms, the cadence
  designer, presets, the console with every command.
- **Load any library or dev scene** from the menus or the console; they are built into the page.
- **Export figures and scenes as downloads**: `figure … to fig.svg` (or `.pdf`), `save x.ron` and
  `journal save x.json` hand the browser a file instead of writing one.
- **Link to a state**: `…/Cavendish/#exec=load comb; panes 2` runs those console commands first, as
  the native `--exec` does.
- **See which commit a page is**: the About box says `built from <revision>`, and the page carries
  `<meta name="revision">`.
- A browser without WebGPU gets a page that says so and names the browsers that work.

What does not work on the web, each refused with the reason where it is asked for: a bundle (a
folder of files), reading a scene, preset or journal by path (use the library names), PNG figures
and pictures of the 3-D view that need pixels read back from the GPU (SVG and PDF work, and views
of voxel bodies are vectors), more than one core for the forward model (§2), the CLI and MCP.

## 2. Design in one page

**Toolchain (the note §1, followed).** No trunk. `cargo xtask web build` = `cargo build --profile web
--target wasm32-unknown-unknown -p cav-app --bin cav-web`, `wasm-bindgen --target web` at the
lock's version (0.2.130, checked), `wasm-opt -O2` from binaryen `version_133` (checked), and
`crates/cav-app/web/index.html` with the revision stamped. One command, the same locally and in CI.
`[profile.web]` inherits release: `opt-level = "s"` except `cav-core` and `cav-sim` at 3, LTO, one
codegen unit, `panic = "abort"`, and **`overflow-checks = true`** (usize is 32 bits on wasm32: a
product that would wrap there panics instead of slipping past a cap).

**Platform seams: one module each, chosen by `cfg(target_arch = "wasm32")`.**

| Crate | Seam | Native | Web |
|---|---|---|---|
| `cav-gpu` | `native.rs` / `web.rs` | makes its device (`Gpu::new`), error scopes, read-back | handed eframe's (`Gpu::from_parts`); `checked` runs the work (errors reach the browser's console); read-back refused |
| `cav-engine` | `forward/threads.rs` / `forward/inline.rs` | two worker threads | the same two jobs run from `Forward::poll`, at most `POLL_BUDGET` (8 ms) a call, the reading first; the same slots, epochs, store and order of summing |
| `cav-engine` | `files/native.rs` / `files/web.rs` | files written where named | kept as downloads (≤ `MAX_DOWNLOAD_BYTES`, 256 MiB) until the app hands them to the browser; folders refused (`files::FOLDERS`) |
| `cav-plot` | `figure/studio.rs` / `figure/studio_web.rs` | the exporter's own device for pixels | no pixels: PNG and renderer views refused, vectors made |
| `cav-app` | `web.rs` (+ `bin/cav-web.rs`) | `main.rs` | eframe's `WebRunner` on `#cavendish`, `#exec=` from the address, downloads |

`Instant` is `web_time::Instant` everywhere it is read in shipped code (std's on native, re-exported;
`performance.now()` on the web). `Engine::settle`'s comparison wait no longer sleeps in 2 ms naps: it
calls the comparison forward's own `settle`, which on the web runs the jobs.

**WebGPU only** (the note §2): wgpu's `webgpu` feature for wasm only (and
`fragile-send-sync-non-atomic-wasm`, so that the figure exporter, which must be `Send`, can hold wgpu
handles in a page with one thread). No WebGL2: S5's kernels need compute.

**Bounded as on native.** Every store keeps its native cap (forward store 256 MiB, trees 256 MiB,
history, journal, log); downloads have their own (256 MiB). wasm32's 4 GiB address space is above
all of them together.

## 4. Demo script

1. Open https://ma1achy.github.io/Cavendish/ — the room, five towers, the timeline.
2. Scene menu → `comb`; Space plays; the signal and periodogram panes show the comb.
3. Console: `load sphere`, `colour mass`, `panes 2`, `look top` — the voxel sphere as a tree.
4. Console: `figure periodogram to comb.svg` — the browser downloads `comb.svg`, its data and record.
5. Help → About: `built from <revision>`.
`cargo xtask demo S17` takes the screenshots headlessly into `docs/slices/S17/`.

## 5. Performance budget

- Page: wasm ≤ 8 MB after wasm-opt, ≤ 3 MB gzipped; first draw within 3 s of a warm load on the
  build PC.
- A frame of the forward model's work on the web: ≤ `POLL_BUDGET` (8 ms) plus one source's
  contribution (not cut; the note's resumable read is in `plan/IDEAS.md`).
- `cargo xtask web` warm: under 1 min after an edit of the app (the LTO build dominates).
- Native tiers: not slower than before the slice.

## 6. Where the plan, the note and this slice disagree

- The note's v1 leaves figures and file downloads out; the owner asked for them, so files go
  through `cav_engine::files` (downloads on the web) and vector figures work.
- The note puts `Instant` behind a small module per crate; `web-time` re-exports std's on native,
  so it is used directly, with no module and no cfg.
- The note gates `cav-plot`'s `headless` module native-only; it compiles on the web (the exporter
  names its types) and refuses at its first read-back, which keeps the seam to one module.
- `strip = true` in the note's profile hides the features section wasm-bindgen reads (it warns);
  the profile does not strip, and wasm-opt drops the names.
- The note's `-Oz` vs `-O2`: measured (§7), `-O2` kept.

### 7.2 The equivalence (R2, R3)

Criterion written before measuring: the same bits where the arithmetic is the same; within 1e-12
of the label's largest magnitude elsewhere. Measured (`cargo xtask web`, wasm under Node.js 24):

- **21,297 numbers; 20,758 the same to the bit.** `point` and `sphere` (signals, the clock,
  readings, periodograms) are identical in every bit: the cube kernel, the audited read and the
  summing order are the same arithmetic on both.
- The 539 that differ are all `comb`'s: 19, 3 and 17 shots of its three signal channels (its
  oscillator's position is a sine) and all 500 bins of its periodogram's power (the FFT's
  twiddles are sines and cosines). **Largest difference 2.3e-16 of the label's largest magnitude**
  (`comb/signal.gradiometer` shot 1276: 5.6688151510529146e-2 against 5.668815151052913e-2), one
  unit in the last place: the maths libraries round `sin` differently.
- Control: a list moved by one last bit is found and named; moved by 1e-3 it fails the tolerance.

What it covers: the engine as the page runs it (the inline forward workers, `web_time`, wasm's
arithmetic and maths library). What it does not: the browser's own JavaScript engine (Node's V8
is the same engine as Chrome's, so a difference there is not expected), and WebGPU, which computes
nothing yet (S5 needs a browser-driven test of its kernels).

### 7.3 Sizes and times

| | bytes |
|---|---|
| `cav-web.wasm` from cargo (profile `web`, not stripped) | 9,196,012 |
| after wasm-bindgen | 6,910,777 |
| after `wasm-opt -O2` (served) | 5,665,963 |
| served, gzip -9 | 2,208,190 |
| `cavendish.js` (glue) | 103,515 |

`-O2` against `-Oz` (measured once, same input): 5,660,931 against 5,515,564 bytes, 2,208,351
against 2,202,383 gzipped: 0.3% smaller over the wire for a slower module and a wasm-opt twice as
long (32 s against 17 s), so `-O2`. `opt-level = 3` for every crate instead of `"s"`: 6.93 MB
(2.49 MB gzipped) and no faster start, so `"s"` with `cav-core` and `cav-sim` at 3.

Load, served from localhost (`cargo xtask demo S17`, headless Chrome): the module arrives in about
25 ms; **the application draws its first frame 1.0 to 1.5 s after the address is opened** for
`room`, `comb` and `sphere` (compiling 5.7 MB of wasm is most of it). Over the internet add the
2.2 MB transfer.

On the web the forward model runs on the page's one thread. `sphere`'s voxel body is one job of
about 5 s in Chrome (it is 4.2 s natively on one thread in a debug build, 1.5 s on eight): before
the rest between long jobs (§2) that job ran inside the first frame, and the page was blank for
6.4 s; with it the page draws at 1.5 s and then holds one frame while the job runs.
`platonic-row` (five voxel bodies, coloured by level) still shows its first frame after 9.3 s:
profiling shows the frames' time in the voxel contributions, and the first frame of that scene
is held by one of them. The resumable contribution in `plan/IDEAS.md` is the cure.

### 7.5 The demo

`cargo xtask demo S17` builds the page, serves it from xtask itself, and photographs it in
headless Chrome with WebGPU (no window): `docs/slices/S17/web-room.png`, `web-comb.png` (signal,

the module never fetched), and `web-console.txt` (each page's console and load times). It also
loads `#exec=load comb; save comb.ron` with downloads allowed and holds the downloaded file to the
native `save`, line for line. Any console error or panic fails the demo.

### 7.6 Departures (one line each)

- No validation case for the equivalence: `cargo xtask validate` runs natively, and a case whose
  numbers come from a wasm run under Node cannot run there; the test in `cargo xtask web` holds
  it instead, with its stated tolerance.
- The Pages workflow builds and deploys but does not run the equivalence (it would double the
  build); the local `web` tier does, before a merge that touches the engine.
- `Engine::settle`'s comparison wait calls the comparison's own `settle` instead of sleeping in
  2 ms naps (std's sleep panics on wasm); the same wait, natively, without the fixed nap.
- The About box said "Slice S1: a point mass"; it now says which revision the build is from.
- Found: a scene saved natively on Windows has CRLF line endings (ron's default), one saved in
  the page LF; the same scene line for line (the demo checks it). Not changed here.

### 7.7 Not verified

- Firefox, Safari and Edge: only Chrome was run (headless, on this PC's GTX 1660 SUPER).
- Touch, phones and small screens: not tried; the layout is the desktop one.
- A figure's download in the page: the demo checks a scene's (`save comb.ron` arrives as a file,
  byte for byte the native `save`); figures go through the same `cav_engine::files::write` but
  were not downloaded headlessly.
