## 1. What the owner can newly do

A first-time user, with no console:

- **Add things.** An **Add** menu, the scene tree's `+` and right-click menu, the palette and the
  Place tool all add the same *starters*: a point mass, a sphere, a cube, a cylinder, the five
  Platonic solids, an oscillating mass, a pendulum, a tower. Each is a valid body or tower, named
  so it is unique, placed where the camera looks (or where the pointer clicks). One undo takes it
  back.
- **Remove, duplicate, rename, frame.** `Delete`, `Ctrl+D`, `F2`, `F` on the selection, from the
  tree or the view, and the same entries on the right-click menu.
- **Move things in the view.** A tool strip (Select `Q`, Move `W`, Place `A`; snap `S`) beside the
  view; the Move tool puts a translate gizmo (three axis arrows and a centre handle) on the
  selection; a drag along an arrow moves the body along that axis, snapped when snap is on; the
  whole drag is one undo. From the keyboard: the *transform session* — arrows move by the snap
  step, `X`/`Y`/`Z` lock an axis, digits type an exact distance, `Enter` keeps, `Esc` cancels.
- **Edit in the inspector.** The properties are sections (the body, its shape, its motion, when it
  is there), each field with its unit and range; lists get add, remove and reorder; any field that
  differs from the scene as it was opened or saved is marked and has a reset.
- **Find anything.** `Ctrl+K` opens a command palette over every action, every starter, every
  library scene and every field of the selection; typing filters, `Enter` runs. `?` shows the
  shortcut sheet, made from the same table as the menus.
- **Use the keyboard for everything** (the spec): `Tab` walks the big scopes, `Enter` goes in,
  `Esc` comes out, arrows move or adjust, a ring (orange: moving; blue: operating) and a
  breadcrumb say where the keys go.
- **Move the camera better.** `F` frames the selection; the wheel zooms toward the pointer; *fly*
  (`Shift+F`, or hold the right mouse button: `W A S D` to move, `E`/`Q` up and down, the mouse or
  arrows to look); `Home` resets the view and can now be undone; camera bookmarks saved in the scene
  (`view save <name>`, `,` and `.` to step through them).
- **Arrange the window.** The side panels resize by dragging their edges (remembered); `Ctrl+Space`
  maximises the active pane and restores it; `F11` full screen; three layouts (Scene, Instrument,
  Analysis) switched from the top bar, each a data file.
- **Start, save and open.** File > New opens a wizard (the array, the surroundings, a starting
  body, the duration); File > New from template opens a library scene; `Ctrl+S` saves (a download
  in the page), `Ctrl+O` opens; the title says `*` while there are unsaved edits.
- **See what happened.** Edit > History (`Ctrl+H`) lists every edit with the line that made it;
  clicking a row undoes or redoes to it. Each edit shows a toast over the footer with an Undo link.
  An empty scene says how to begin in the tree, not in the console.

Everything above is also a console line, so the CLI and an agent over MCP can do it; every scene
edit is one undoable `Command` through `Engine::apply`, whether it came from the view, a panel, a
key or the palette.

## 2. Design in one page

**The keyboard (`cav-app/src/keyboard.rs`).** The spec's §11, as pure logic: `Keyboard { nav_on,
mode, focus: Vec<Id>, popup, typing }`, a `FocusTree` of scopes and elements that the frame
registers into as it draws (visual order = registration order, declared once by the big-scope
list), and one function `Keyboard::route(&tree, key) -> Vec<Effect>` that applies the fixed
priority (typing, popup, global, scope shortcuts inside out, mode handling). Held keys go through
`Repeat` (500 ms, then every 40 ms) on the frame clock, so a held key is testable without a real
clock. Effects are things the frame then does (`Click(id)`, `Adjust(id, step)`, `Run(line)`,
`StartTyping(id)`, `Open(window)`): the router never touches the engine. Nothing in it is
journalled or undoable.

**The big scopes, fixed (the note §3.10.1, as built):** 1 top bar · 2 tool strip · 3 scene tree ·
4 viewport · 5 inspector · 6 timeline · 7 footer. The note's 7th, "Analysis", is not a scope of its
own here: plots are a pane's content inside the viewport (the Analysis *layout* gives them the
room). Windows (palette, shortcut sheet, history, wizard, open/save, about, the console) are not
big scopes; each is a list of sections.

**GUI as data (`crates/cav-app/ui/*.ron`, embedded).** `actions.ron`: every action's id, label,
menu, console line, owning scope, key chord and enabling rule; the menu bar, the right-click menus,
the palette, the tool strip's tooltips and the `?` sheet are views of it. `tools.ron`: the tool
strip (id, label, key, behaviour). `layouts.ron`: the three layouts. `scopes.ron`: the big scopes'
ids, names and order. Starters are scene data in `cav-sim` (`scenes/starters.ron`), so `cav exec`
and MCP use them too (`add sphere at 2 0 1`). Code keeps the mechanisms (the router, the widgets,
the gizmo's maths); data keeps the choices. A bad file is a test failure that names its line.

**One path.** A gizmo drag, a typed distance, a held arrow in a transform session and an inspector
field all end in the same `Command::Set { path: bodies[i].motion.<anchor>, continues }`; a run is
one journal entry and one undo (the engine's existing coalescing). A run that ends where it began
(a cancelled session) leaves no undo step (`History::continued` drops a step whose undo and redo
are equal). Add, duplicate and place are `Command::Insert`; delete is `Command::Remove`; the wizard
is one `Command::Load`.

**Engine additions** (each also a console line): `ViewCommand::Camera { pane, target, yaw, pitch,
distance }` (fly, frame, zoom-to-cursor, bookmark recall in one command); `Home` an undoable step
(`Edit::View`), every other camera move not; `add <starter> [at x y z]`; scene `views` (bookmarks)
with `view save|goto|drop <name>`; `Engine::baseline()` (the scene as opened or saved) for reset
and the unsaved mark; the history's steps carry the line that made them, for the history list.

**Owner's defaults for the calls the note left open** (PROGRESS, 25 Nov 2026): tools on Q/W/E/R
(Q Select, W Move; E and R stay reserved for Rotate and Scale, which move to S19; Place is `A`);
**Esc cancels a transform session and Enter keeps it** (written into the spec as its one local
exception, §7 of `docs/design/keyboard.md`); F3 hides the GUI and Ctrl+K opens the palette; camera
moves are not undoable except Home.

### 7.3 Decided (calls worth a second look)

1. **The router's priority puts a session's own keys before the globals but Esc/Enter**: in a fly
   or transform session Ctrl+Z still undoes, but no letter changes tool.
2. **A menu opened from the keyboard is the palette filtered to that menu** (egui's menus are not
   reachable by keys); Enter on a menu title opens it.
3. **Arrows step the playhead only in the scrubber** (Enter first), as the spec requires; before
   they did from anywhere. `1`–`9` select towers in the viewport and tree.
4. **The history drops a step whose undo equals its redo** (a set to the same value; a drag that
   returns; a cancelled session), parked while a drag may go on. Live and replayed histories agree.
5. **Esc in a transform session cancels** by moving back as the run's last step (no redo left);
   Enter keeps (the owner's default, written into `docs/design/keyboard.md`).
6. **Home is undoable** by an `Edit::View` step; it clears the redo stack as any edit does.
7. **Tools are E-and-R-free**: Q Select, W Move, A Place, S snap; E and R are kept for S19's
   Rotate and Scale.
8. **The body's inspector shows the body's fields only**; the instrument and cadence are the scene's
   and the towers' (`BODY_VISITS` restated 48 → 24 with the reason in the test).
9. **The palette's exception**: while typing in its query ↑ ↓ choose, Enter runs, one Esc closes.
10. **Step lines are derived from edits** (`Edit::line`) rather than stored: the memory bound of
    `the_undo_history_is_bounded_by_bytes` was written before and holds unchanged.
11. **The outliner narrows on a small window** (210–262 points) to keep the figure's share with
    the new tool and options strips; the inspector keeps its 264.
12. **Starters live in `cav-sim`** (`scenes/starters.ron`), so `cav exec` and MCP add the same
    things; `add <starter> at x y z` is console grammar beside `add <list> <json>`.
