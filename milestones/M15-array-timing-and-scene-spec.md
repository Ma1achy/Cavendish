# M15 — Per-tower timing and the scene spec (plan / implementation brief)

> **Status: planned — nothing here is built.** Depends on: M11. Unblocks: M13's configuration
> panels, console and per-tower timeline (they edit and display what this milestone defines).
> **This is a data-contract change** (`StateBundle` gains a field; `Scenario` gains per-tower
> settings): the spec is edited first, per the `doc-sync` rule.
>
> **Goal.** Two things the engine cannot express today and the GUI needs before it can be more than a
> player: (1) towers that fire on their own clocks, and (2) one serialisable description of a scene
> that a file, the GUI, the console and Python all read and write.

---

## 1. What is there now

- `Scenario.schedule: Schedule { times: Vec<f64>, mask: Vec<bool> }` — **one** list of measurement
  times shared by every tower. `StateBundle.time` is `(T,)`; `signal` is `(T, D)`.
- `InstrumentConfig` (T, launch velocity, baseline, `fine_dt`) is one value for the whole array.
- A scene is Rust code: `Scenario::scene(sources, array, schedule, seed)`. There is no file format
  and nothing a GUI could edit. `phase_model` sits on `Scenario` with a `DEFERRED` note about its
  proper home (the "config seating" item).

## 2. Requirements

| ID | Requirement |
|---|---|
| M15-R1 | **Per-tower timing.** Each tower has `Timing { offset, jitter }`: its `ℓ`-th readout is at `t_ℓ + offset_d (+ jitter)`. All towers still take the same number of shots `T` (the tensors stay rectangular). |
| M15-R2 | **Per-tower instrument overrides.** A tower may override `t_half`, `u0`, `ifo_sep` and `fine_dt`; unset fields inherit the array default. |
| M15-R3 | `StateBundle` gains `detector_time: (T, D)` — the actual readout time of each tower's shot. `time: (T,)` stays as the cycle's nominal time; source tracks stay sampled on it. Optional per-tower track samples are a `FieldSet` flag, off by default. |
| M15-R4 | Everything downstream uses the tower's own time: the propagation integral's flight window `[t − 2T_d, t]`, ULDM, the noise realisations, the Lomb–Scargle periodogram, `GridField`'s response phase. |
| M15-R5 | **Synchronous scenes are unchanged.** With all offsets zero and no overrides, every pre-existing bundle field is bit-identical to before; `detector_time[ℓ][d] == time[ℓ]`. |
| M15-R6 | **`SceneSpec`** — a plain serialisable value describing a whole scene: sources (kind + parameters), array (towers: placement, timing, overrides), air (room, grid, heat sources), noise stack, ULDM, schedule, seed, phase model, field set, outputs. `SceneSpec::build() -> Scenario`. Round-trips through a text file. |
| M15-R7 | **Addressable.** Every field of a spec has a path (`array.tower[2].timing.offset`); `get(path)`, `set(path, value)` and `schema()` (type, unit, range, doc string per path) exist. This is what the GUI's property panels, the console and Python bind to. |
| M15-R8 | **Invalidation is declared, not guessed.** Each path belongs to a stage — `View`, `Readout` (noise, masks), `Forward` (array, timing, instrument), `Air`, `Dynamics`, `Shape` — and `SceneSpec::diff(a, b)` returns the earliest stage that must be re-run. |
| M15-R9 | `phase_model` and the instrument configuration are seated in the spec (the deferred "config seating"), without editing the forward-model crates' numerics. |

## 3. Design

```rust
pub struct TowerSpec { pub placement: Placement, pub timing: Timing, pub instrument: InstrumentOverride, pub label: String }
pub struct Timing    { pub offset: f64 /* s */, pub jitter: f64 /* s rms, keyed by (seed, tower) */ }
pub struct SceneSpec { pub sources: Vec<SourceSpec>, pub array: ArraySpec, pub air: Option<AirSpec>,
                       pub schedule: ScheduleSpec, pub noise: NoiseSpec, pub uldm: Option<UldmSpec>,
                       pub instrument: InstrumentConfig, pub phase_model: PhaseModelKind,
                       pub field_set: FieldSet, pub seed: u64 }
pub enum SourceSpec  { Point{..}, Primitive{..}, Mesh{..}, Walker{..}, Plate{..}, Dropped{..}, Radiator{..}, .. }
```

- **Where timing lives.** `instrument::DetectorArray` is in the validated spine and is not edited:
  per-tower timing and overrides sit on `Scenario` as `towers: Vec<TowerSettings>`, parallel to
  `array.detectors`, defaulting to synchronous and inherited.
- **Where it lives.** A new L3 crate `spec` (`spec → scenario, physics, world, shape`), so `scenario`
  stays free of the physics dependency. `viewer`, `sdk` and the CLI depend on `spec`.
- **Format.** RON via `serde` (already a workspace dependency): it writes Rust enums and structs
  without a mapping layer, and allows comments. One new dependency (`ron`). Units are in the field
  names' doc strings and the schema, SI throughout.
- **Paths and schema** are generated by a small derive-free visitor over the spec types (a hand-written
  `fn visit(&mut self, v: &mut dyn Visitor)` per struct — about thirty fields; no reflection crate).
- **Why equal shot counts.** Unequal cadences make `signal` ragged, which changes every consumer
  (the bundle, the torch dataset, the viewer). Offsets and jitter cover desynchronised firing; a
  tower with a genuinely different cadence is a separate open item (§7).
- **`generate::run`** becomes a loop over `(ℓ, d)` with `t = detector_time[ℓ][d]` and the tower's
  resolved `InstrumentConfig`; arms are built per distinct config (cached by value). Rigid-source
  amortisation is per `(source, time)`, so desynchronised towers cost up to `D×` the pose
  evaluations — measured and reported, not assumed away.

**A physical consequence to carry into the docs.** Anything that differences towers to cancel a
common mode — the ULDM channel, laser phase noise if it is ever modelled as shared — cancels only
when the towers sample the same instant. With staggered firing the common mode is sampled at
different times and the cancellation is partial, by an amount set by the common mode's spectrum and
the offset. The engine will compute this correctly (R4); `design/uldm.md` and `design/noise.md` need a
paragraph saying so, because it changes how a downstream estimator should combine towers.

## 4. Tests

| Level | Test | Asserts | Tol |
|---|---|---|---|
| unit | `zero_offsets_are_the_old_schedule` | `detector_time` equals `time` in every column; all prior fields bit-identical | **exact** |
| unit | `offset_shifts_one_tower_only` | tower `d` with offset `δ` reads what the synchronous scene reads at `t + δ`; others unchanged | ≤1e-12 |
| unit | `per_tower_t_half_changes_its_window` | a tower with a shorter `T` integrates `[t − 2T_d, t]`; equals a single-tower scene with that config | ≤1e-12 |
| unit | `jitter_is_keyed_not_ordered` | same `(seed, tower)` → same jitter for any batch order or thread count | exact |
| unit | `uldm_is_sampled_at_tower_time` | common-mode value per tower equals the field at `detector_time` | ≤1e-12 |
| unit | `grid_response_keyed_by_tower_phase` | staggered towers build one response each; aligned ones share none incorrectly | structural |
| unit | `spec_roundtrips` | spec → RON → spec identical; comments survive a load (not a save) | exact |
| unit | `spec_builds_the_same_scenario` | `SceneSpec::build()` for each library scene = the hand-written Rust scene | bundle bit-identical |
| unit | `every_path_gets_and_sets` | for every schema path: `set(get())` is a no-op; type and range errors are `Err`, not panics | exact |
| unit | `diff_names_the_earliest_stage` | camera → `View`; noise → `Readout`; tower offset → `Forward`; radiator power → `Air`; drop height → `Dynamics`; pitch → `Shape` | exact |
| integration | `staggered_array_end_to_end` | five towers, offsets `d·2T/5`: runs, decomposes exactly, periodogram per tower on its own times | ≤1e-10 |
| e2e | `bundle_hash` (field-wise) | 24 v1 scenes: every pre-existing field identical; only `detector_time` is new | exact |

## 7. Open questions

- **Different cadences per tower** (ragged `T_d`). Needs a per-tower bundle or a padded tensor with a
  validity mask; decide when a real schedule asks for it.
- **Is asynchronous firing how the real array would run?** Whether towers share a laser, and so are
  constrained to fire together, is an instrument question for George, not a software one. The engine
  should permit both; the default stays synchronous.
- **Python.** `SceneSpec` as a dict/dataclass mirror in the SDK, or RON strings passed through — to
  be settled with the M7 conventions.
